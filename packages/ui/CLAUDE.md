All shadcn/ui-equivalent components — including the chat-oriented additions (Attachment, Bubble, Code Block, Marker, Message, Message Scroller, Questionnaire, Trace) and Direction; Typography stays a recipe page — exist in `packages/ui` with registry sidecars and a doc page under `/components/:name`. Three behavior tiers, matching basecoat's own split: pure Tailwind/no-JS (Button, Badge, Card, ...), native-element (Dialog/Sheet via `<dialog>`, Accordion/Collapsible via `<details>`, Popover/Combobox via `<details>`), and hand-rolled Airstream `Var`/`EventBus` state machines where no native element or CSS-only trick covers it (DropdownMenu, ContextMenu, Menubar via DropdownMenu reuse, Resizable via drag listeners, InputOTP, Calendar). `packages/webcomponents` exposes all 63 component families through `Sc*`/`ScPrimitives` custom-element classes; check their registrations for the exact tag names. Some compound wrappers intentionally expose a narrower JSON/named-slot protocol than the Laminar API; test that protocol against your use case rather than assuming full feature parity.

The chat-oriented components rely on utilities that are not part of Tailwind — `shimmer`, `shimmer-none`, `scroll-fade-x|y|b`, `scrollbar-thin|none|gutter-stable`. They are defined with `@utility` in `packages/theme/tokens.css` (mirrored into `packages/cli/assets/styles/tokens.css` and `apps/web/src/styles/globals.css`); keep the three copies in step. Those components ship docs demos in `apps/web/.../site/NewComponentExamples.scala` but no Web Component wrappers yet.
